# data/synthetic — synthetic fixtures only

Everything in this folder is invented. Nothing here comes from, or describes, a real institution or person (guard rails 3–5).

## What counts as synthetic
A value is synthetic only if it was made up for testing and cannot be traced to a real institution, person, document or application. Copying a real value and "changing a digit" is **not** synthetic.

## Naming patterns (use these, nothing else)
| Item | Pattern | Example |
|---|---|---|
| Institution name | `Demo Institute of Technology NN` / `Demo College of Engineering NN` | Demo Institute of Technology 03 |
| Trust / society | `Demo Educational Trust NN` | Demo Educational Trust 03 |
| Application ID | `1-9` + 10 digits (the `1-9…` range is reserved for demo data) | `1-90000004217` |
| Permanent ID | `1-9` + 6 digits | `1-9000317` |
| Faculty / trustee / signatory | tokens only (`fac_tok_…`, `trs_tok_…`, `sig_tok_…`) | `fac_tok_demo_0001` |
| Usernames | `<role>.<region>.demo`, `<role>.demo`, `institution.demoNN` | `rb.southern.demo` |
| Email | `@example.invalid` only (RFC 2606 reserved) | `rb.southern.demo@example.invalid` |
| Licence / certificate numbers | the real *pattern*, demo range `9###` | `9017/RFL/NMSB/2026` |
| Place names | `Demo Town NN`, `Demo District NN` | Demo District 07 |
| Coordinates | inside the sea or a clearly fake grid; never a real campus | — |

## Generated demo cases (`cases/`)
`cases/<case>/` holds one synthetic case each: `case.json` (case metadata, the portal draft header, the e-stamp/notary metadata and the document list with upload times), `snapshot.json` (ApplicationSnapshot), `affidavit-sworn.pdf` (text-layer sworn Affidavit 2 with an e-stamp page, a notary block and real test signatures, every page marked SYNTHETIC), `audited-accounts.pdf` (one-page audited statement with the auditor block, UDIN when planted), `truth.json` (what the M5 generator planted) and `truth-m6.json` (what the M6 generator planted). The engines never read the truth files. They are generated by `make synth` from `packages/forensics/src/satya_forensics/synth/` (which uses the M5 generator in `packages/affidavit/src/satya_affidavit/synth/`); never edit them by hand. `make synth-check` (also run by the test suite) fails if they are stale.

## Test PKI (`pki/`) and registers (`registry/`)
- `pki/satya-test-root.pem` ("SATYA TEST TRUST ANCHOR"), `pki/satya-test-sub-ca-1.pem` and `pki/satya-test-sub-ca-1.crl` are the **public** half of the synthetic test PKI (`packages/forensics/src/satya_forensics/pki.py`). Keys are Ed25519, derived from public seeds at test time and never stored. The UI always calls this root "TEST TRUST ANCHOR". It is not a CA and proves nothing outside this test suite.
- `registry/prior-filings.json` is a synthetic register of earlier filings (2025-26 e-stamp certificate numbers per demo profile; FY 2024-25 UDINs; one sister-filing UDIN per auditor) that the M6 reuse checks compare against. Stamp numbers follow the SHCIL pattern (`IN-TN` + 14 digits + letter) in a demo range; UDINs follow YY + membership no. (demo range `99xxxx`) + 6 letters + 4 digits and are not real.

## Banned
- Any file from `data/real-samples/` (git-ignored; never enters a cloud session, a commit, a log or an issue).
- Real names, phone numbers, emails, Aadhaar, PAN, DOB, signatures, real application/permanent/faculty IDs.
- Real institution names or website content.
- Real AICTE logos, State Emblem or AICTE branding.

## Guard
CI runs `infra/scripts/real-data-guard.sh` on every push. Values that look like personal-data patterns but are documented synthetic fixtures must be listed in `.real-data-allowlist` with a reason.
