# Decisions: UI polish v0.8

- Tokens: v0.8 tokens use unprefixed names (`--label-verified-bg`), so tokens.json has a `raw` group the generator emits without the group prefix. The prototype-strip hexes were also removed from the spec §8 summary line so the generator's coverage check passes.
- Fonts: the spec names "Noto Sans 500" for labels, but only Public Sans, Noto Sans Mono and Noto Sans Devanagari are installed and no new dependencies are allowed. Labels and badges use the body font (Public Sans, new 500 weight from the existing package); Devanagari text falls back to Noto Sans Devanagari as before.
- Hindi keys added in this work are marked `[VERIFY] needs review` in hi.review.json (the existing convention, which messages.test.ts enforces).
- SourceTag "Test trust anchor": the API has no `trust_anchor.kind` field yet, so SignatureBadge shows the tag on every performed signature check (not on absent, wet-seal or N/A rows). The API still returns `trust_anchor_label` unchanged (contract field and tests); the workbench no longer prints it.
- SourceTag "Simulated source": shown when a check's source mode is `mock`. API source names lost their "(MOCK SOURCE)" suffix; the ledger `tag` of new source-response entries is now "simulated source". Existing ledgers are replaced by `make demo-reset`.
- The viewer toolbar shows the Test trust anchor tag because the viewer opens documents whose signatures were checked against the test root.
- FlagCard tags: SIG-* findings carry Test trust anchor; STAMP-REUSE and UDIN-REUSE (registry lookups) carry Simulated source.
- API why sentence for SIG-UNTRUSTED now says "the trust anchor" instead of the upper-case test label.
- Queue columns: the spec's sortable columns (Application, Awaiting, Submitted, Last activity) did not all exist. Added "Awaiting" (undisposed findings, shown as "n of total"), "Submitted" and "Last activity". Institution is no longer sortable; Labels, Reasons and Risk are not sortable.
- submitted_at / last_activity_at come from the ledger (first and last entry of the case, which are the intake and the latest check or decision). If a case has no ledger entry yet they fall back to its last check time. Fixture upload dates are not used because they lie in the future of a demo run.
- Case status: the four Slice D values (awaiting_review, in_review, reviewed, no_findings) are replaced by the five from the spec (not_started, in_review, waiting_on_institution, referred, all_flags_decided) everywhere, API and web, so the queue, case page and Overview agree. "Open" escalation = the latest decision on a flag is escalate_clarify or escalate_refer; clarify wins over refer; a case without flags is all_flags_decided.
- Sort parameters are validated against a whitelist; an unknown sort or dir is a 422 VALIDATION_FAILED problem response. With no sort the API orders by undisposed_flags descending inside each band and echoes `sort.default: true`; the UI then shows no active column.
- SortIndicator triangles: 8px base by 5px high (the spec's 4x5 read as half-base by height).
- The "demo" word is removed from the empty-queue copy ("approval portal", not "mock portal"); honesty is carried by SourceTag.
- Header search: the spec lists a search field without behaviour. It is a plain GET form to the queue with `q` (whitelisted to letters, digits, space, dot, dash, max 40) that filters by application ID or institution name. It shows for the Regulation Bureau role only (the only role with a queue).
- The user menu identity block is a plain element above the menu (not focusable); the menu holds Language (single-select group), Accessibility settings (link) and Sign out (submits the existing /signout POST, which ends the Keycloak session).
- The footer drops the About link (spec lists Website policies, Accessibility, Help, Sitemap); the About page stays reachable from the sitemap page.
- Alerts: the API now returns `severity` (critical, warning, info), `created_at` (the case's latest check run), `doc_id`, `label`, `flag_id`, `aph_clause`, `source` and a stable `alert_key`. Severity by subtype: new_high_band critical (High), certificate_expired and source_unavailable_task warning (Medium), expiring_soon info (Low).
- Unread state has no server store in this build, so it is a short HttpOnly, Secure, SameSite=Lax cookie (`satya_seen_alerts`, newest 40 alert keys, 30 days) per browser. "Open flag" goes through `/alerts/open`, which marks the alert seen and redirects to a target rebuilt from validated ids (no open redirect). Alerts without a flag say "Open document" and land on the documents section.
- The rail notification card did not exist; it is added as the top unread alert in the same card style, for the Regulation Bureau role, rendered inside Suspense with a quiet API call so it can never break or delay a page.
- Overview API: `GET /v1/overview?ay=&region=` uses the queue's role check and region scope plus a dedicated per-user quota (`SATYA_OVERVIEW_RATE_LIMIT`, default 30/minute). `ay` must be a supported year (422 UNSUPPORTED_AY), `region` a lower-case name matching `[a-z][a-z_]{1,19}` that the official may see (422 for a malformed value, 403 SCOPE_DENIED for a region outside scope; `national` needs the national group). Default `ay` is the latest supported year.
- Expiring windows: no 60-day window exists in the repo (the alert uses 30 days), so the Overview shows 30/60/90 as cumulative counts of documents whose check carries a `valid_to` within that many days, judged as of the case's document upload date like the alerts. `top` lists the 5 closest, with `doc_type` = document slot plus a `doc_title` for display.
- Manual task age comes from the ledger `manual_task.created` entry. Source status is "unavailable" only when every answer from an adapter was source_unavailable; the offline chain check is always "answering".
- Overview "Open manual tasks" should link to the manual verification page, but RB-09 is not built (no dead navigation). Each task links to its case (documents section) and the panel footer links to the queue filtered to the Source unavailable label.
- Overview "Recent decisions" rows link to the audit trail filtered to that case; the panel footer opens the whole audit trail.
- The Overview loading skeleton is static (no shimmer), as asked; other skeletons keep their existing style.
- `/` sends the Regulation Bureau role to `/overview`; a sign-in callback URL (for example a case deep link) is honoured first, as before. `?view=overview` is gone from the queue, rail, sitemap and metadata.
- Label in Name (axe, WCAG 2.5.3): the queue "Open case" link aria-label is now "Open case for application {aid}" (it began with different words before), the user menu initials are drawn from a data attribute by CSS so they do not count as visible text, and the Overview label links take their name from their content.
- The engine text for SIG-IMAGE and SIG-UNTRUSTED expected values (packages/forensics) now says "the trust anchor" instead of printing the upper-case test label, so the workbench shows no TEST TRUST ANCHOR string. Guard rail 10 in CLAUDE.md is reworded to the tags.
- Checks ran against a local harness (the real gateway app on the synthetic cases with an in-memory ledger seeded like make demo-reset, plus a production build of the web app and a signed session cookie), because this environment has no Docker daemon. Keycloak login, sign-out, the institution 403 and the full compose stack are covered only by CI.
- CI found the rail alert card (one API call per page) pushing the e2e user over the 300/minute per-user quota (web logged "Workbench API answered 429"). The card's quiet API call is now cached per session for 20 seconds; the quota itself is unchanged.
- CI found that Next prefetched the alert "Open flag" links in the viewport, which ran `/alerts/open` and marked every alert seen before anyone clicked. Those links (and the rail card's) now use `prefetch={false}`, and polish.cjs checks the card in `main` and prints its text.
- The CI browser run still hit 429s after the rail cache: the API's per-IP window (120/minute, counted on every endpoint) sees all workbench users as the single web container, and the Overview, rail card and sort re-renders add calls. The stack default is now 600/minute (`.env.example` and compose); the per-user quota (300/minute), the overview quota and the per-client portal limit are unchanged.
- polish.cjs now waits (up to 5 s) for React Aria to restore focus to the user menu trigger after Escape instead of reading it once; the one CI failure left was that timing, not the menu.
