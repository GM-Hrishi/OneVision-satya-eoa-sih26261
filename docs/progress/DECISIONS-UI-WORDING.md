# Decisions: UI wording (Slice W)
W-1 Roadmap lines (arrive with M3/M6/M7/M11) are replaced with true statements that point to the tab where the check really appears, or say what the file did not give (a file that could not be read). No line promises a future module.
W-2 `hi.json` rewritten with plain Hindi for the same keys; each changed key is listed in `hi.review.json` as [VERIFY].
W-3 `/v1/meta` `adapters_note` now states that source answers come from offline checks or simulated services; it no longer names modules.
W-4 Schema descriptions (affidavit-diff, case-verification, event-envelope) lose "Slice", "arrive" and module codes; they now describe what the field holds.
W-5 New additive schema pieces: `ReadNote` ($defs in document.schema.json), `AffidavitDiff.comparison` (optional) and `CaseVerificationDocument.read` (optional). They are optional because the engine tests validate engine output against the schema and the engine (packages/affidavit) is not touched; the API adds them.
W-6 D4 root cause: the Case tab read `Workflow.analyse` (M6 result, then the source hub with its stored-register answers, then the scan gating). The Verification tab and the per-document endpoint read `CaseRepository.verification`, the bare M6 result: no hub, no scan gating. The audited statement therefore had no source answer on one tab (Source unavailable, NO CHANNEL) and the simulated ICAI answer SRC_MATCH on the other (Verified).
W-7 D4 choice: both tabs read `Workflow.analyse`. The Case tab is the one that writes the ledger (source.response, check.run, manual_task.created), so it is the record; a source answer is stored per check run and `analyse` is cached by file hash, so neither tab does a live lookup. `/verification` and `/documents/{doc}/verification` now come from `Workflow.verification`/`document_verification`; `case_verification` takes the Case-tab answers as an argument. A valid uploader signature still never makes a document verified (the label comes from the checks), and a scan stays manual review required. Result: the audited statement of an unblemished case is Verified, with the Simulated source tag, on both tabs. The earlier test that expected Source unavailable for it asserted the old M6-only view and is updated.
W-8 D1: `AffidavitDiff.comparison` is added by the API (`comparison_of` in cases.py) from the document read, not by the engine. state is `compared` only for a file with a text layer and no scan reason; a scan (read by OCR or not) and an unreadable file are `not_compared`. The UI additionally refuses to say "matches" when the structure is incomplete.
W-9 D5: ledger kinds the API can write are the seven workflow constants, `case.replay`, and the inbound portal event types in shared-types. Each has an English and Hindi label under demo.audit.event; the audit page falls back to "Other event" for an unlabelled kind and a test fails when a kind has no label.
