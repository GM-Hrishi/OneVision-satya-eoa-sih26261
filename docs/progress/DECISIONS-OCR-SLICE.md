## Decisions
- O-1 Branch: the session is bound to `claude/magical-euler-7a0r6m` and may not push elsewhere, so that branch is used instead of `ocr-scan-fallback`. The PR is opened from it.
- O-2 New workspace package `packages/ocr` (`satya_ocr`): `inspect` (pikepdf + pypdfium2 page classes), `pipeline.read_document` (never raises), `engine` (`OcrEngine`, `FakeOcrEngine`, `PaddleOcrEngine`), `reasons`, `synth` (Pillow scans), `testing`. M5 (`extract(data, ocr)`, `CaseInput.ocr/unreadable_pages`) and M6 (`read_pages(pdf, ocr)`, `M6Input.reads`) take its output; the gateway wires it in `cases.py` (`read_of`, cached by SHA-256, one document at a time) and `workflow.py`.
- O-3 Reason codes (names from the prompt, convention UPPER_SNAKE like `SIG_IMAGE_ONLY`) [ASSUMED]: `SCAN_IMAGE_ONLY` (scan read by OCR and still needing a human, OCR not attempted, OCR timed out), `OCR_LOW_CONFIDENCE`, `OCR_UNAVAILABLE` (also: the engine raised), `DOC_UNREADABLE` (encrypted, damaged, no pages, all blank, more pages than the cap). Ten "why" variants in `satya_ocr/reasons.py`, same keys under `demo.ocr.why.*` in the workbench messages (English complete; Hindi keys present with English text, listed in `hi.review.json` as [VERIFY]).
- O-4 Thresholds (all `SATYA_OCR_*`, defaults in `OcrSettings`): max 50 pages (extra pages recorded as `skipped`, the file is `DOC_UNREADABLE`/too_large), 20 non-space characters for a text layer, mean OCR confidence 0.80 (lowest page decides; 0.80 itself passes), 30 s per page, 300 s per document, page images capped at 3000 px on the long side (200 dpi). The 0.80 default is the prompt's [ASSUMED] value, not tuned on real scans.
- O-5 A scan fallback does not raise the risk band: documents with a scan or unreadable reason are left out of the band's label input, and `SIG-*` flags on them are left out of its flag input. Real M5 findings from OCR text still count. Why: an unreadable file is not evidence of wrongdoing. It creates a manual task (Overview manual-task count) and a ledger entry `document.read`.
- O-6 Every scan, even one OCR read well, stays `manual_review_required` (reason `SCAN_IMAGE_ONLY`, `format` check `m3:OCR-READ:<variant>`): `document_label` takes the most severe check, so a source lookup that passes can never lift it to `verified`. Tested for confidence 0, 0.5, 0.95 and 1.0.
- O-7 OCR-derived M5 flags: `preliminary_indicator: true`, label capped at `manual_review_required`, `confidence` capped by the page's OCR confidence, `extracted_source.doc_label` ends ", read by OCR (NN%)". No schema change (provenance enum untouched). Tables are not read from OCR pages (no ruled-line geometry); `pending` gains the `ocr` section.
- O-8 Blocked files (unreadable, low confidence, unavailable) skip the M5 text run and the M6 signature/text run: M5 returns its existing empty diff, M6 returns one `format` check. Source hub is skipped too (no identifier was read).
- O-9 A damaged PDF that passes the name/`%PDF-`/`%%EOF` sniff is no longer rolled back with `UPLOAD_UNREADABLE`: it is stored and lands on manual review (`DOC_UNREADABLE`). Non-PDF content is still refused (`UPLOAD_CONTENT_REJECTED`). `test_upload_rules_and_rerun` was updated for this.
- O-10 Abuse limits: uploads also count against `SATYA_OCR_RATE_LIMIT` (10/minute per user), one OCR document at a time (semaphore), per-page and per-document time limits. A timed-out engine thread cannot be killed; it is abandoned and the document falls back.
- O-11 `pikepdf` 10.17.0 (MPL-2.0), `pypdfium2` 5.14.0 (Apache-2.0 or BSD-3-Clause), `pillow` 13.0.0 (MIT-CMU/HPND): already in the lockfile through pyHanko/pdfplumber, now declared by `satya-ocr`. No PyMuPDF, no Ultralytics.
- O-12 The `ocr` dependency group is `packages/ocr/requirements-ocr.txt` (paddleocr 3.7.0 Apache-2.0, paddlepaddle 3.3.1 Apache-2.0; paddlex 3.7.2 Apache-2.0 comes with it), not a uv extra: paddlex pins `pyyaml==6.0.2` while the workspace pins 6.0.3, so declaring it would make the lockfile unsatisfiable. Installed by `services/api/Dockerfile` with `ARG WITH_OCR` (default 1 in docker-compose, 0 in CI). Models (PP-OCRv5 mobile det, en PP-OCRv5 mobile rec) are baked at build by `packages/ocr/scripts/fetch_models.py`. Python 3.13 install works (checked in a scratch venv); model download is blocked in the cloud sandbox (two attempts, BOS and Hugging Face), so the real engine is NOT verified here.
